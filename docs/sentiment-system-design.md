# 情感分析系统需求分析与总体设计

## 3.1 系统需求分析

### 3.1.1 功能需求分析

为满足耳机评论数据的自动化分析需求，系统需要围绕“数据处理—模型分析—结果呈现”这一主线构建完整功能链路。结合业务目标与后续实验需求，系统功能需求具体如下。

#### （1）数据导入功能
系统应能够读取开源耳机评论数据集，支持对评论文本、属性信息、情感词、情感标签等关键字段进行识别与提取，并完成基础数据加载。该模块既要满足离线实验的数据接入要求，也要为后续批量分析提供标准化数据来源。

#### （2）文本预处理功能
由于原始评论数据往往存在重复记录、噪声字符、表达不规范等问题，系统需要具备文本预处理能力，包括去重、清洗、分词、停用词过滤以及标准化处理等操作。通过该模块，可以将原始评论转换为适合机器学习与深度学习模型使用的规范化输入，提高后续情感分类的准确性与稳定性。

#### （3）情感分类功能
系统应能够基于训练完成的情感分类模型，对评论文本进行情感倾向识别，并输出正面、负面或中性三类结果。该功能不仅要支持单条评论的即时分析，还应支持批量评论分析，以满足论文实验、业务统计和实际应用场景下的不同需求。

#### （4）模型对比功能
为了验证不同模型在耳机评论情感分析任务中的适用性，系统应能够对 SVM、TextCNN 和 BERT 三种模型进行统一训练、评估与对比。系统需要输出准确率、精确率、召回率、F1 值等评价指标，并以可视化或表格方式展示模型效果差异，为模型选择与优化提供依据。

#### （5）细粒度分析功能
除整体情感分类外，系统还应结合评论中的属性信息，对价格、音质、功能、舒适度、外观等不同维度开展细粒度情感分析。通过对各属性维度下情感分布进行统计，可以更加准确地识别用户对产品不同方面的评价倾向，为后续产品优化和用户洞察提供支持。

#### （6）痛点挖掘功能
系统应能够从负面评论中进一步提取用户集中反映的问题。具体而言，可先筛选出负面评论，再结合聚类分析和高频词统计等方法，对用户投诉重点和共性问题进行归纳，如续航不足、佩戴不适、降噪效果一般等。该模块的目标是帮助研究者和分析人员从大规模评论中快速识别产品痛点。

#### （7）结果展示与导出功能
系统应能够对情感分类结果、模型评估结果和统计分析结果进行可视化展示，例如柱状图、饼图、词云图和对比表等，并支持分析结果导出。导出内容可包括分类结果文件、模型评价结果和统计报表，以便用于论文撰写、实验复现和业务汇报。

### 3.1.2 性能需求分析

除功能需求外，系统还需要满足以下性能要求，以保证其在研究和应用场景中的可用性。

#### （1）正确性
系统应保证数据处理、模型预测和结果统计过程的正确性。无论是在数据导入、预处理还是分类分析阶段，都需要确保输出结果与输入数据之间具备一致、可靠的逻辑关系，从而为实验结论和应用决策提供可信支撑。

#### （2）运行效率
系统应具备较好的运行效率，能够在合理时间内完成评论数据处理、模型训练与情感分析任务。对于批量评论分析场景，系统需要在保证分析质量的前提下尽可能缩短处理时间，提升整体使用体验。

#### （3）可扩展性
系统应采用模块化设计，使其便于后续替换或新增分类模型，并能够平滑扩展到其他商品评论场景，如手机、电脑、家电等。通过保留清晰的数据接口与模型接口，系统可以在未来研究中支持更多算法和多领域迁移任务。

#### （4）可维护性
系统应具备较好的可维护性，代码结构清晰、模块划分明确、功能职责边界清楚。这样既有利于后续功能迭代，也便于研究者对实验流程进行调整、优化和复现。

#### （5）易用性
系统应提供较友好的交互与展示方式，便于用户完成数据导入、预处理、模型分析以及结果查看等操作。对于研究者而言，应方便组织实验流程；对于商品分析人员而言，应降低使用门槛，使其能够快速获取直观分析结果。

### 3.1.3 用户需求分析

系统的主要使用对象包括研究者和商品分析人员，两类用户在使用目标上各有侧重，因此系统设计需要兼顾研究性与实用性。

#### （1）研究者需求
对于研究者而言，系统应支持从数据处理、模型训练到实验对比、结果输出的完整流程，便于开展情感分析相关研究工作。研究者关注的重点包括：

- 能否方便地导入和清洗数据；
- 能否灵活切换不同模型进行实验；
- 能否输出规范的评估指标与图表；
- 能否为论文撰写提供可复用、可解释的实验结果。

#### （2）商品分析人员需求
对于商品分析人员而言，系统更强调分析效率和结果直观性。其核心需求包括：

- 快速识别评论整体情感倾向；
- 及时发现用户重点关注的产品属性；
- 从负面评论中提炼用户痛点问题；
- 通过图表和报表形式查看分析结果，用于产品优化和运营决策。

#### （3）综合需求结论
因此，系统在设计时既要具备面向研究的模型训练、实验对比与结果导出能力，也要具备面向应用的快速分析、属性统计与可视化展示能力，从而实现研究性与实用性的统一。

## 3.2 系统功能模块总览

根据第一张系统功能模块总览图，整个情感分析系统可以划分为五个核心层次：数据层、预处理层、分析层、挖掘层和展示层。

### （1）数据层
数据层主要负责原始评论数据的接入与管理，是系统运行的基础。其核心任务是导入开源耳机评论数据集，并对评论文本、属性信息、情感词和标签等字段进行解析，为后续处理提供统一数据来源。

### （2）预处理层
预处理层主要负责对原始数据进行规范化处理，包括数据清洗、去重、分词、停用词过滤和文本标准化等。该层的作用是消除噪声、提高数据质量，并为传统机器学习模型和深度学习模型提供一致的输入格式。

### （3）分析层
分析层是系统的核心功能层，主要包括情感分类和模型对比两部分。

- 在情感分类方面，系统支持对评论文本进行正面、负面、中性三分类；
- 在模型对比方面，系统集成 SVM、TextCNN 和 BERT 三类模型，并统一输出评价指标，形成横向对比结果。

这一层直接决定系统的分析能力与实验价值。

### （4）挖掘层
挖掘层在基础情感分类结果之上，进一步开展更深层次的信息提炼，主要包括细粒度分析与痛点挖掘。

- 细粒度分析用于识别价格、音质、功能、舒适度、外观等属性维度上的情感分布；
- 痛点挖掘则聚焦负面评论，通过聚类分析、高频词统计等方法总结用户主要不满点。

该层体现了系统从“情感识别”向“问题发现”和“决策支持”的延伸。

### （5）展示层
展示层用于对系统处理和分析结果进行可视化呈现与导出，包括分类结果展示、模型效果对比、属性情感统计、痛点词汇展示以及报表导出等。该层直接面向用户，是系统可用性与实用性的重要体现。

## 3.3 系统整体框架说明

根据第二张系统整体框架图，系统整体可划分为输入模块、处理分析模块和输出模块三个部分，形成较为完整的闭环流程。

### 3.3.1 输入模块
输入模块主要包括数据集导入与原始评论接入。其作用是将耳机评论数据以结构化形式输入系统，为后续文本处理和模型分析提供数据基础。该模块通常还应具备字段映射、格式检查和数据完整性校验等能力，以保证输入数据的可用性。

### 3.3.2 处理分析模块
处理分析模块是系统框架中的核心部分，主要包括以下几个子模块：

#### （1）文本预处理模块
负责完成数据清洗、分词、停用词过滤、标准化等处理任务，为下游模型提供统一输入。

#### （2）情感分类模块
负责调用训练好的 SVM、TextCNN、BERT 等模型，对评论文本进行情感极性识别，并输出分类结果。

#### （3）模型评估模块
负责从准确率、精确率、召回率、F1 值等维度对不同模型进行评价，并将评估结果用于模型优选。

#### （4）细粒度分析模块
负责将情感结果与评论属性相结合，对不同产品维度进行统计分析，以识别用户对各属性的评价差异。

#### （5）痛点挖掘模块
负责筛选负面评论，结合高频词分析、聚类方法等提取用户集中反馈的问题，形成重点问题列表。

### 3.3.3 输出模块
输出模块主要面向最终用户，负责将系统分析结果进行整理、展示和导出。其输出形式包括：

- 情感分类结果；
- 模型评估结果；
- 属性级情感统计结果；
- 用户痛点分析结果；
- 可视化图表与导出报表。

该模块既服务于论文研究中的实验结果展示，也服务于商品分析场景中的业务汇报和决策支持。

## 3.4 系统设计思路总结

综合上述需求分析与框架设计，本系统遵循“数据导入—文本预处理—情感分类—模型对比—细粒度分析—痛点挖掘—结果展示与导出”的总体流程，具备以下特点：

1. **功能完整**：覆盖数据接入、分类分析、深度挖掘和结果展示全过程；
2. **结构清晰**：按照输入、处理、输出的思路进行模块化组织；
3. **兼顾研究与应用**：既支持模型实验对比，也支持面向业务的评论洞察；
4. **便于扩展**：后续可引入更多预训练模型、更多商品品类和更多可视化方式。

上述设计能够较好地满足耳机评论情感分析任务的研究需求与实际应用需求，也为系统后续实现与优化奠定了基础。
